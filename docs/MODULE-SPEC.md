# Module Contract (MODULE-SPEC)

Every module under `src/core-modules/<name>/` or `src/app-modules/<name>/` must follow this contract so that the Planner, Architect, and module agents can work consistently.

## Directory Layout

```
src/core-modules/<module-name>/   # or src/app-modules/<module-name>/
  functions/       # Lambda handlers (handler.js and any triggers)
  schemas/         # Mongoose or DynamoDB model files
  graphql/         # One or more .graphql files (use extend type Query / extend type Mutation)
  resolvers/       # AppSync JS resolver files (one per query/mutation field)
  MODULE.md        # This module's spec (data models, events, permissions, dependencies)
```

## MODULE.md Contents

1. **Data Models** – List of entities and their fields (and which DB: mongodb vs dynamodb).
2. **GraphQL Schema** – Types, Queries, Mutations this module adds.
3. **Events Published** – EventBridge detail types and payload shape.
4. **Events Consumed** – Which events this module subscribes to (and what it does).
5. **Permissions** – List of `module:resource:action` strings this module uses.
6. **Dependencies** – Other modules this module depends on (e.g. Tenant, User).
7. **Database Choice** – mongodb or dynamodb and brief reasoning.

## Handler Requirements

- Resolve context with `resolveTenant(event)` from the common layer.
- Check permissions with `requirePermission(ctx, 'module:resource:action')` before each operation.
- Use `handleError(error, event)` for consistent error responses.
- Use BaseRepository or MongoRepository for DB access so `tenant_id` is always injected.
- Publish EventBridge events for state-changing operations (create, update, delete, publish, etc.) using `publishEvent(source, detailType, detail)`.

## GraphQL

- Module schema files use `extend type Query` and `extend type Mutation` so they can be merged. The merge script (**scripts/merge-graphql.sh**) flattens all extend blocks into single root `type Query` and `type Mutation` definitions in the output schema for AWS AppSync compatibility (AppSync does not support `extend type`).
- List operations return a Connection type with `items` and `nextCursor`.
- Use shared types from `common.graphql` (PaginationInput, AWSDateTime, AWSJSON, etc.).

## Adding a New Module

1. Run `./scripts/generate-module.sh <module-name> [--type app|core]` to scaffold from _template (default: app → src/app-modules/; core → src/core-modules/).
2. Implement MODULE.md, handlers, schemas, graphql, resolvers.
3. Add the module's Lambda(s), DataSource(s), and Resolvers to **stacks/core/<module-name>.yaml** or **stacks/app/<module-name>.yaml** (use `scripts/generate-sam-resources.sh <module-name>` to emit a snippet). For app modules in a multi-app setup, add the module to **app-configs/<app>.yaml** (e.g. `generate-module.sh <name> --type app --app <app-name>`). Run **scripts/compose-template.sh** (or **compose-template.sh --app <app-name>**) to regenerate the deployable template. Do not edit template.yaml or template.<app>.yaml by hand — they are composed from stacks and app-config.
4. Add the module's Query/Mutation fields and types; run **scripts/merge-graphql.sh** to regenerate the root schema (or **merge-graphql.sh --app <app-name>** for schema.<app>.graphql).
5. AppSyncServiceRole is generated by compose-template.sh from the enabled modules list; no manual update needed.
6. Verify `docs/agents/<module-name>-agent.SKILL.md` was auto-generated. If not, copy `docs/agents/_template.SKILL.md`, replace `{{MODULE_NAME}}` and `{{MODULE_PATH}}`, and add a row to `docs/agents/REGISTRY.md`.
