# SAM Template Agent

> Type: Cross-cutting (invoked during Phase 3 — Implement) — Automate deployable template resource generation for new modules and operations

When invoked: After a vertical agent adds a new module or new GraphQL operations, add the module's Lambda, AppSync DataSource, and Resolvers to the **stacks** so the composed template includes them. The deployable template is **not** hand-edited: it is generated by **scripts/compose-template.sh** from **app-config.yaml** (or **app-configs/<app>.yaml** with **--app <app>**) and the YAML files under **stacks/** (stacks/infrastructure.yaml, stacks/core/<module>.yaml, stacks/app/<module>.yaml). AppSyncServiceRole is generated by compose-template.sh from the enabled modules list. Follow .cursor/rules/sam-template.mdc.

## Context (read in order)
1. Read **app-config.yaml** (or **app-configs/<app>.yaml** for a specific app) — which modules are enabled. Read **stacks/** — existing Lambda, DataSource, Resolver fragments (stacks/infrastructure.yaml, stacks/core/*.yaml, stacks/app/*.yaml).
2. Read **docs/MODULE-SPEC.md** — directory layout, handler requirements.
3. Read the affected **MODULE.md** — GraphQL operations (Queries, Mutations).
4. List **src/core-modules/<module>/resolvers/*.js** and **src/app-modules/<module>/resolvers/*.js** — each file corresponds to one GraphQL field (filename without .js = field name).
5. Read **src/core-modules/<module>/functions/handler.js or src/app-modules/<module>/functions/handler.js** — confirm single handler entrypoint (e.g. handler.handler).

## When to invoke
- **New module added** (e.g. after ./scripts/generate-module.sh): Add Lambda, DataSource, and Resolvers to **stacks/core/<module>.yaml** or **stacks/app/<module>.yaml**; ensure the module is listed in app-config (app-config.yaml or app-configs/<app>.yaml). Run **compose-template.sh** (or **compose-template.sh --app <app>**).
- **New operation added** (new resolver file and handler case): Add one new Resolver to the module's stacks file; ensure schema has the field (GraphQL Schema Agent). Re-run compose-template.sh.
- **Lambda configuration change** (e.g. new env var, new policy): Update the module's Lambda resource in its stacks/core or stacks/app file; re-run compose-template.sh.

## Naming conventions
- **Logical IDs**: Use PascalCase prefix from module name. Examples: form-management → FormFunction, FormDataSource, FormGetResolver, FormCreateResolver. tenant-management → TenantFunction, TenantDataSource, TenantGetResolver.
- **Physical names**: Use `!Sub '${ProjectName}-<module>-${Environment}'` for Lambda FunctionName (e.g. `${ProjectName}-form-${Environment}`). Layer and other resources follow existing template pattern.
- **DataSource Name**: `<ModulePrefix>DataSource` (e.g. FormDataSource). Resolver logical ID: `<ModulePrefix><FieldNameInPascalCase>Resolver` (e.g. FormGetResolver, FormCreateResolver).

## SAM conventions (from sam-template.mdc)
- All resource names use !Sub with ${ProjectName} and ${Environment}.
- Every Lambda attaches CommonLayer and PackagesLayer.
- Every Lambda that publishes events has EventBridgePutEventsPolicy (and EventBusName: !Ref AppEventBus).
- Tag all Lambdas with Environment: !Ref Environment, ModuleName: <module-name>, and ManagedBy: CloudFormation where appropriate.
- Lambda CodeUri: src/core-modules/<module-name>/ or src/app-modules/<module-name>/. Handler: functions/handler.handler (or functions/<name>.handler for triggers).
- Resolver: TypeName Query or Mutation, FieldName = resolver filename without .js, DataSourceName = !GetAtt <ModulePrefix>DataSource.Name, CodeUri: src/core-modules/<module>/resolvers/<file>.js or src/app-modules/<module>/resolvers/<file>.js, Kind: UNIT, Runtime: APPSYNC_JS 1.0.0.

## Actions for new module
1. Run **scripts/generate-sam-resources.sh <module-name>** to emit a YAML snippet.
2. Save the snippet to **stacks/core/<module-name>.yaml** (core) or **stacks/app/<module-name>.yaml** (app). Ensure Lambda, DataSource, and one Resolver per resolver file are included; add EventBridgePutEventsPolicy if MODULE.md lists Events Published.
3. Add the module to app config: **app-config.yaml** (default app) or **app-configs/<app>.yaml** (e.g. via generate-module.sh --app <app>).
4. Run **scripts/compose-template.sh** (or **compose-template.sh --app <app-name>**) to regenerate template.yaml or template.<app>.yaml. Do not edit template.yaml or template.<app>.yaml by hand.

## Output
- Produce a **diff** of the new or updated stacks file (stacks/core/<module>.yaml or stacks/app/<module>.yaml).
- Run **compose-template.sh** [--app <app>] so the deployable template is updated.
